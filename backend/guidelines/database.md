# Backend — Database & Migration Guidelines

> Rules for PostgreSQL schema design, Alembic migrations, soft deletes, and audit logging.

---

## Database

- **Production:** PostgreSQL 15+
- **Dev/Testing:** SQLite (in-memory for unit tests only — never staging or production)

---

## Alembic Migration Rules

- All schema changes go through Alembic — never alter the database manually
- Generate migrations with: `alembic revision --autogenerate -m "description"`
- Every migration must implement `downgrade()` — all migrations must be reversible
- Name migrations descriptively: `add_tenant_id_to_vehicles`, `create_audit_logs_table`
- Review autogenerated migrations before committing — Alembic sometimes misses type changes

---

## Required Columns (Every Operational Model)

Every operational ORM model must include these columns:

| Column | Type | Notes |
|---|---|---|
| `id` | `String` (UUID, PK) | Prefixed: `veh-uuid`, `drv-uuid`, etc. |
| `tenant_id` | `String` (FK → tenants) | Non-nullable, indexed |
| `is_deleted` | `Boolean` | Default `False`; for soft deletes |
| `created_at` | `DateTime (UTC)` | `server_default=func.now()` |
| `updated_at` | `DateTime (UTC)` | `onupdate=func.now()` |

Exceptions:
- `Tenant` — has `is_active` instead of `is_deleted`; has no `tenant_id` (it is the root)
- `AuditLog` — immutable; no `is_deleted`, no `updated_at`; never modified after insert

---

## Soft Deletes (Required)

- **Never** use `DELETE` statements on operational records
- Set `is_deleted = TRUE` instead
- All list queries must filter: `WHERE is_deleted = FALSE`
- Expose a `DELETE /api/v1/vehicles/{id}` endpoint that performs a soft delete + audit log entry

---

## Audit Logging (Required)

Call `audit_service.log()` for every mutation on critical entities (`Users`, `Vehicles`, `Routes`, `Trips`, `Tenants`):

```python
await audit_service.log(
    db=db,
    user_id=current_user.id,
    tenant_id=current_user.tenant_id,
    entity_type="Vehicle",
    entity_id=vehicle.id,
    action_type="update",          # create | update | soft_delete | login | impersonate
    metadata={"before": {...}, "after": {...}}  # JSON diff
)
```

The `audit_logs` table is **immutable** — records are never updated or deleted.

## Required Indexes

Add these indexes in migrations:

```sql
CREATE INDEX idx_vehicles_tenant_id      ON vehicles(tenant_id);
CREATE INDEX idx_routes_tenant_id        ON routes(tenant_id);
CREATE INDEX idx_trips_tenant_id         ON trips(tenant_id);
CREATE INDEX idx_drivers_tenant_id       ON drivers(tenant_id);
CREATE INDEX idx_alerts_tenant_id        ON alerts(tenant_id);
CREATE INDEX idx_audit_logs_tenant_id    ON audit_logs(tenant_id);
CREATE INDEX idx_vehicles_status         ON vehicles(status);
CREATE INDEX idx_trips_status            ON trips(status);
CREATE INDEX idx_alerts_is_acknowledged  ON alerts(is_acknowledged);
```

---

## Performance Guidelines

- Use `async def` and `AsyncSession` for all DB operations
- Use `selectinload()` for eager-loading related models to avoid N+1 queries
- Cache analytics aggregations in Redis with a 60-second TTL, keyed by `tenant_id`
- Never return unbounded query results — always paginate list endpoints
